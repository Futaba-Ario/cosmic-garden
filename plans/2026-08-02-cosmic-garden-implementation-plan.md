# 星雲の庭（Cosmic Garden）実装計画書

## 1. 文書情報

- 作成日: 2026-08-02
- 参照設計: `plans/2026-08-02-cosmic-garden-design.md`
- 想定期間: 1〜2週間（標準10営業日）
- 対象: PC／スマートフォン向けインタラクティブWebアート
- 実装方針: 最小限の宇宙を早期に動かし、垂直分割で操作、演出、UI、安定性を段階的に追加する

## 2. 目標と対象範囲

### 2.1 目標

端末の現在時刻と季節によって表情が変わり、マウスまたはタッチ操作で星、光跡、小銀河に触れられる単一ページ作品を完成させる。インストールやログインを不要とし、URL共有と画像保存に対応する。

### 2.2 実装対象

- 朝、昼、夕、深夜と四季を組み合わせたテーマ制御
- Three.js／WebGLによる背景、星、星雲、光跡、小銀河の描画
- Pointer Eventsによるマウス／タッチ共通操作
- 長押しの蓄積表現と、解放時の小銀河生成
- 初回操作案内、現在テーマ、音、共有、画像保存のUI
- Web Audio APIによる控えめな環境音
- 画面リサイズ、向き変更、ページ非表示への追従
- 自動品質調整、`prefers-reduced-motion`、WebGL非対応時のフォールバック
- 単体テスト、ブラウザテスト、テーマ別スクリーンショット確認

### 2.3 対象外

- アカウント、ランキング、スコア、保存データの同期
- サーバー、データベース、外部API
- 複数ページ構成、管理画面
- 端末間での作品状態共有
- 本格的な楽曲再生やユーザー音源のアップロード

## 3. 技術選定

| 項目 | 採用技術 | 用途 |
| --- | --- | --- |
| ビルド | Vite | 開発サーバー、TypeScript／GLSLのバンドル |
| 言語 | TypeScript | 状態、入力、描画責務の型安全な分離 |
| 3D／GPU描画 | Three.js | WebGL初期化、シーン、カメラ、BufferGeometry、ShaderMaterial |
| シェーダー | GLSL | 星雲の揺らぎ、色混合、発光、粒子表現 |
| 音 | Web Audio API | 初回操作後に開始する生成的な環境音 |
| 単体テスト | Vitest | テーマ計算、入力判定、品質調整の検証 |
| ブラウザテスト | Playwright | 操作、フォールバック、主要画面サイズ、スクリーンショットの検証 |
| 静的検査 | ESLint、TypeScript | コード品質と型エラーの検出 |

追加ランタイム依存は原則として `three` のみに抑える。GLSLはViteの `?raw` インポートを使用し、専用ローダーを追加しない。共有、画像保存、音声はブラウザ標準APIで実装する。

## 5. 共通データ設計

### 5.1 テーマ状態

`ThemeState` は以下を保持する。

- 時刻帯: `morning | day | evening | night`
- 季節: `spring | summer | autumn | winter`
- 背景色、星色、星雲色2〜3色
- 背景光量、星雲発光量、粒子密度、揺らぎ速度
- 時刻帯境界の補間率

時刻帯の切り替えを不連続にせず、境界前後を補間する。初期実装では端末のローカル日時を使い、テストおよび開発時のみURLパラメーター `?debugDate=2026-04-01T06:00:00` で日時を固定できるようにする。

### 5.2 ポインター状態

`PointerState` は正規化画面座標、ワールド座標、移動速度、押下時刻、押下継続率、入力種別、アクティブ状態を保持する。DOMイベントからレンダリング用状態への変換は1か所で行い、各エフェクトはイベントそのものに依存しない。

### 5.3 品質状態

品質を `high | medium | low | reduced` の4段階とし、粒子数、描画倍率、星雲サンプル量、軌跡上限、小銀河上限をプロファイル化する。`reduced` は低負荷設定に加えて動きの振幅と点滅を抑える。

## 6. 実装フェーズ

### フェーズ1: プロジェクト基盤と静的シェル（1日目）

#### 作業内容

1. Viteのvanilla TypeScript構成を初期化する。
2. `three`、Vitest、Playwright、ESLintと必要な型定義を導入する。
3. `dev`、`build`、`preview`、`typecheck`、`lint`、`test`、`test:e2e` のnpm scriptsを定義する。
4. 全画面キャンバス、UIレイヤー、フォールバック領域を持つHTML／CSSを作る。
5. WebGL2またはWebGLの利用可否、タッチ、`prefers-reduced-motion` を判定する。
6. `CosmicGardenApp` の初期化、開始、停止、破棄のライフサイクルを作る。

#### 対象ファイル

`package.json`、`index.html`、`src/main.ts`、`src/styles.css`、`src/app/*`、`src/utils/capabilities.ts`

#### 検証

- `npm run dev` で空の全画面キャンバスとUI領域が表示される。
- `npm run build`、`npm run typecheck`、`npm run lint` が成功する。
- 360×800、768×1024、1440×900でスクロールバーや余白が出ない。

#### 完了条件

アプリの起動／停止が一元管理され、以後の機能を追加できる基盤がある。

### フェーズ2: テーマ制御と最小宇宙（2〜3日目）

#### 作業内容

1. 月から四季、時刻から朝／昼／夕／深夜を判定する純粋関数を作る。
2. 時刻帯と季節のパレット、光量、粒子密度を定義する。
3. 境界時刻の前後でテーマ値を連続補間する。
4. Three.jsのrenderer、scene、orthographicまたはperspective cameraを初期化する。
5. GPUの `Points` と `BufferGeometry` で星空を描画する。
6. フルスクリーン平面とシェーダーで星雲背景を描画する。
7. 初期表示を数秒でフェードインさせる。
8. リサイズ時はシーンを再生成せず、camera、resolution uniform、renderer sizeを更新する。

#### 対象ファイル

`src/theme/*`、`src/rendering/*`、`src/rendering/shaders/*`、`tests/unit/resolveTheme.test.ts`

#### 検証

- 代表日時16パターン（4時刻帯×4季節）で期待するテーマが選択される。
- 時刻帯境界の直前／直後で色と光量が急変しない。
- リサイズと画面回転後も描画が伸びたり欠けたりしない。
- 初回ロード時に大きなフリーズがなく、宇宙がフェードインする。

#### 完了条件

操作なしでも、日時と季節を反映した作品として成立する最小版が表示される。

### フェーズ3: 共通入力と主要インタラクション（4〜5日目）

#### 作業内容

1. Pointer Eventsを登録し、マウス、ペン、タッチを同じ状態へ正規化する。
2. 画面座標を描画ワールド座標へ変換する。
3. 移動距離と経過時間からポインター速度を平滑化して求める。
4. 近傍の星がポインターへ緩やかに引き寄せられ、離れると戻る表現を追加する。
5. 一定間隔で光跡粒子を生成し、速度に応じて寿命と長さを変える。
6. 遅い移動では星が周囲を漂う係数を強める。
7. 押下継続時間を0〜1へ変換し、エネルギー蓄積の光輪を表示する。
8. 長押し成立後の解放で小銀河を生成し、拡大、回転、減衰後に破棄する。
9. `pointercancel`、画面外移動、複数タッチを安全に処理する。初期版では先頭の1ポインターのみ作品操作に使用する。

#### 対象ファイル

`src/interaction/*`、`src/effects/*`、`tests/unit/PointerController.test.ts`、`tests/e2e/interaction.spec.ts`

#### 検証

- マウスとタッチで星の引力と光跡が同じ意図で動作する。
- 短いクリック／タップでは小銀河が生成されない。
- 長押し中の蓄積が視認でき、解放時に1個だけ小銀河が生成される。
- 操作を繰り返してもオブジェクト数が上限を超えず、破棄済みGPU資源が残らない。

#### 完了条件

設計書にある「近づける」「動かす」「長押しして離す」の3操作が明確に体験できる。

### フェーズ4: UI、音、共有、画像保存（6日目）

#### 作業内容

1. 初回のみ操作案内を表示し、最初の有効操作でフェードアウトする。
2. 現在時刻と季節テーマ名を控えめに表示する。
3. 操作説明パネルと、キーボード／スクリーンリーダー向けラベルを追加する。
4. Web Audio APIで環境音を構成し、最初のユーザー操作後にのみ開始する。
5. 音のオン／オフ状態を切り替え、初期値はオフまたは明示操作待ちとする。
6. Web Share APIでURLを共有し、非対応時はClipboard APIへフォールバックする。
7. キャプチャ要求時に1フレーム描画した直後、canvasをPNG Blobへ変換して保存する。
8. 共有、コピー、保存、音声開始の失敗を非破壊のトーストで通知する。

#### 対象ファイル

`src/ui/*`、`src/audio/AmbientAudio.ts`、`src/styles.css`、`tests/e2e/smoke.spec.ts`

#### 検証

- 自動再生制限に触れず、ユーザー操作後のみ音声コンテキストが開始する。
- 共有非対応環境でもURLコピーが利用できる。
- 保存したPNGが黒画面やUI欠けではなく、現在の宇宙を含む。
- UI操作が作品側の長押しや光跡を誤発火させない。

#### 完了条件

初見ユーザーが操作を理解でき、作品の共有と画像保存を完了できる。

### フェーズ5: 適応品質、アクセシビリティ、フォールバック（7日目）

#### 作業内容

1. CPUコア数、端末メモリ（利用可能な場合）、画面サイズ、DPRから初期品質を選ぶ。
2. DPRを品質別上限で制限し、過剰なピクセル描画を防ぐ。
3. 移動平均FPSを測定し、低FPSが一定時間続いた場合だけ1段階下げる。
4. 頻繁な品質往復を防ぐクールダウンとヒステリシスを設ける。
5. 品質変更時に粒子上限やシェーダー負荷を段階的に調整する。
6. ページ非表示時にanimation frameと音を停止し、復帰時に再開する。
7. `prefers-reduced-motion` では動き、点滅、引力、長い軌跡を抑える。
8. WebGL非対応または初期化失敗時に、日時テーマのCSSグラデーションと静止星空を表示する。

#### 対象ファイル

`src/performance/*`、`src/fallback/StaticFallback.ts`、`src/utils/lifecycle.ts`、`tests/unit/QualityManager.test.ts`、`tests/e2e/fallback.spec.ts`

#### 検証

- 人為的にFPS低下を与えると品質が段階的に下がる。
- 一時的なフレーム落ちだけでは品質が変わらない。
- 非表示タブで描画と音が停止する。
- reduced motionおよびWebGL無効の条件でも情報と雰囲気が保たれる。

#### 完了条件

高性能端末では品質を活かし、低性能／制限環境では体験を壊さず負荷を下げられる。

### フェーズ6: 統合テストとビジュアル調整（8〜9日目）

#### 作業内容

1. 主要ブラウザ幅と代表日時によるPlaywrightシナリオを整備する。
2. 朝、昼、夕、深夜と四季の基準スクリーンショットを作る。
3. 描画のランダムシードと日時をテスト時に固定し、差分を安定させる。
4. Chrome系、Firefox、WebKit相当で起動と基本操作を確認する。
5. iOS SafariおよびAndroid Chromeの実機でタッチ、長押し、回転、共有、保存を確認する。
6. 360px幅でUIが重ならず、セーフエリア内に収まるよう調整する。
7. 星雲のコントラスト、星の密度、光跡寿命、小銀河の視認性を最終調整する。

#### 対象ファイル

`tests/e2e/*`、`playwright.config.ts`、各描画／UIファイル

#### 検証

- `npm run test` と `npm run test:e2e` が成功する。
- 基準画像との差分が許容範囲内である。
- 主要操作でコンソールエラーと未処理Promise rejectionが発生しない。
- 実機で誤スクロール、ダブルタップ拡大、長押しメニューが作品操作を妨げない。

#### 完了条件

PCとスマートフォンで一貫した体験があり、テーマごとの見た目が完成条件を満たす。

### フェーズ7: リリース準備（10日目）

#### 作業内容

1. production buildを作成し、preview環境で最終確認する。
2. JavaScript、シェーダー、アセットの出力サイズを確認する。
3. 初期ロード時間、平均FPS、メモリ増加、描画オブジェクト数を計測する。
4. READMEへ開発、テスト、ビルド、デバッグ日時指定、操作方法を記載する。
5. 静的ホスティング向けのベースパスとキャッシュ方針を確認する。
6. 最終受け入れチェックリストを実施する。

#### 対象ファイル

`README.md`、`vite.config.ts`、必要な設定ファイル

#### 検証

- クリーン環境で依存導入からbuildまで再現できる。
- 配信先相当のサブパスまたはルートパスでアセットが404にならない。
- デバッグ用日時指定が本番UIに露出しない。

#### 完了条件

静的ファイルとして公開でき、URLを共有すれば主要ブラウザですぐ作品を体験できる。

## 8. テスト計画

### 8.1 単体テスト

- 月境界における季節判定
- 時刻帯の中央値および境界値
- 日付／時刻補間率の範囲と連続性
- ポインター速度の平滑化と長押し成立判定
- FPS閾値、継続時間、クールダウンによる品質遷移
- 上限到達時のエフェクト再利用と破棄

### 8.2 ブラウザ自動テスト

- 初期表示、案内表示、最初の操作後の案内消去
- マウス移動、タップ、長押し、pointer cancel
- 音声開始拒否、共有非対応、Clipboard失敗
- WebGL非対応フォールバック
- ページ非表示／復帰
- 主要ビューポートでのUI配置

### 8.3 ビジュアルテスト

- デバッグ日時と乱数シードを固定する。
- 最低限、春の朝、夏の昼、秋の夕、冬の深夜を基準画像化する。
- 余力があれば4時刻帯×4季節の16パターンへ拡張する。
- GPUやブラウザ差で生じる微小差を許容しつつ、大きな色、配置、欠落を検出する。

### 8.4 手動・実機テスト

- PC: 最新安定版のChrome、Firefox、Edge、Safari相当環境
- スマートフォン: iOS Safari、Android Chrome
- 低性能条件: DevTools CPU slowdown、DPRの高いスマートフォン、低品質強制
- 例外条件: WebGL無効、音声拒否、共有不可、画像保存失敗、オフライン再読込

## 9. 性能予算

初期値として以下を目標にし、実機計測後に調整する。

- デスクトップ高品質: 平均55〜60 FPSを目標
- モバイル中品質: 平均45 FPS以上を目標
- 品質低下判定: 移動平均が30 FPS未満の状態が数秒継続した場合
- DPR上限: 高品質2.0、中品質1.5、低品質1.0を目安
- 星粒子: 品質別に約2,000〜20,000個
- 同時光跡粒子と小銀河: 固定上限を設け、プールで再利用
- 初期表示: 通常回線で主要描画開始まで3秒以内を目標

品質判定の具体値は端末検証で確定する。見た目の豪華さより、入力への反応遅延とフレーム安定性を優先する。

## 10. エラー処理方針

- WebGLコンテキスト生成失敗: 静的フォールバックへ即時移行する。
- WebGL context lost: 描画を停止して復旧を試み、復旧不可ならフォールバックへ移行する。
- シェーダーコンパイル失敗: 開発時は詳細を出し、本番ではフォールバックと簡潔な通知を表示する。
- 音声開始失敗: 無音のまま作品を継続し、音ボタンだけ状態を戻す。
- 共有／コピー／保存失敗: 描画を止めず、再試行可能なメッセージを表示する。
- 未知の初期化エラー: 可能な範囲で静的フォールバックを表示し、白画面を避ける。

## 11. 主なリスクと対応

| リスク | 影響 | 対応 |
| --- | --- | --- |
| 星雲シェーダーが端末差で重い | モバイルで操作不能 | シェーダー反復数、DPR、粒子数を品質プロファイル化 |
| Three.jsオブジェクトの破棄漏れ | 長時間操作でメモリ増加 | オブジェクトプール、上限、`dispose()`責務を各システムに定義 |
| 長押しがOS操作と競合 | 小銀河を作れない | canvasに適切な`touch-action`を指定し、UI領域は入力対象外にする |
| Canvas画像が空または黒い | 保存機能が成立しない | 保存要求フレームで明示的に再描画してからBlob化する |
| テーマの組み合わせで色が濁る | 16テーマの一部が破綻 | 時刻光量と季節パレットの責務を分け、代表画像で回帰確認 |
| 自動品質が頻繁に上下する | 見た目が不安定 | 継続時間、ヒステリシス、クールダウンを導入 |
| ブラウザの音声／共有制限 | 機能が反応しない | ユーザー操作起点、標準APIの段階的フォールバック |

## 14. 実装開始時の順序

最初の作業単位はフェーズ1とし、プロジェクト初期化後すぐに `npm run build`、`npm run typecheck`、`npm run lint` が通る状態を作る。その後、機能ごとではなく各フェーズの完了条件を満たしてから次へ進む。各マイルストーンでPCとスマートフォン幅の両方を確認し、端末固有の問題を最終日まで持ち越さない。
